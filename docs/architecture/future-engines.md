# Future Engines

## Purpose

This document describes future conceptual engines of Maloja Plana.

These are architecture directions only.

No implementation decisions are finalized.

## Derived State Engine

Purpose:
Generate calm assistance from existing data relationships.

Examples:
- document expiry warnings
- potential subsidy reminders
- household change consequences
- relocation implications
- insurance continuity hints

Important:
The engine should suggest possibilities, not legal conclusions.

## Household Engine

Purpose:
Represent real-world living situations.

Examples:
- couples
- families
- shared apartments
- separated parents
- multi-generation households
- temporary residents

Requirements:
- non-discriminatory
- flexible
- canton-aware
- resilient to edge cases

## Canton Rule Engine

Purpose:
Represent canton-specific logic without hardcoding assumptions everywhere.

Possible domains:
- taxes
- subsidies
- social systems
- deadlines
- forms
- school systems

Important:
Rules should remain explainable and traceable.

## Document Generation Engine

Purpose:
Generate structured exports and templates.

Possible outputs:
- checklists
- summaries
- printable packets
- authority preparation
- life-event bundles

Important:
Users must control all exports manually.

## Reminder Intelligence Engine

Purpose:
Create calm timeline awareness.

Examples:
- renewal reminders
- document expiry
- recurring deadlines
- retirement preparation
- insurance changes

Important:
No anxiety-based notification systems.

## Relationship Mapping Engine

Purpose:
Support the Spinnennetz / Life Web concept.

Examples:
- housing affects taxes
- employment affects insurance
- family changes affect benefits
- canton changes affect obligations

Important:
Relationships should remain visually calm and understandable.

## Security Hardening Engine

Purpose:
Strengthen trust over time.

Future possibilities:
- stronger encryption layers
- secure export modes
- selective redaction
- backup integrity validation
- local audit trails

## Important Principle

Every engine must:
- reduce cognitive overload
- remain explainable
- preserve user autonomy
- function offline where possible
- avoid hidden behavior
