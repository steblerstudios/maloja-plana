# Data Lineage & Provenance

## Objective

Define how data lineage, provenance,
and traceability are managed across
all platform workflows.

The system must support:
- reproducibility
- auditability
- regulatory traceability
- source attribution
- transformation tracking
- rollback analysis
- validation evidence generation

---

# Core Principles

## Full Traceability

Every critical datum must be traceable to:
- originating source
- acquisition method
- transformation steps
- validation events
- approval events
- consuming workflows

No critical data should exist without lineage.

---

## Immutable Provenance

Provenance records must be:
- immutable
- timestamped
- versioned
- attributable
- reproducible

Historical lineage must never be overwritten.

---

## Human Accountability

Human actions affecting data must record:
- actor
- timestamp
- purpose
- approval context
- affected records

---

## AI Accountability

AI-generated outputs must record:
- model version
- runtime version
- context version
- prompt lineage
- validation results
- approval state

---

# Lineage Scope

## Included Entities

Lineage applies to:
- source datasets
- transformed datasets
- derived records
- agent outputs
- validation artifacts
- approvals
- audit records
- reports
- exports

# Provenance Model

# 1. Source Provenance

## Requirements

Every imported source must track:
- source owner
- acquisition method
- retrieval timestamp
- source version
- licensing status
- checksum/hash
- retrieval operator

## Examples

- BAG datasets
- MedReg snapshots
- Swissmedic exports
- external APIs
- uploaded files

---

# 2. Transformation Provenance

## Requirements

Each transformation step records:
- transformation ID
- input dataset
- output dataset
- transformation logic version
- execution timestamp
- executing actor/agent
- validation result

## Examples

- normalization
- deduplication
- mapping
- enrichment
- classification

---

# 3. Agent Provenance

## Requirements

Every agent execution must record:
- agent identifier
- runtime version
- prompt/context version
- tools invoked
- execution duration
- generated outputs
- validation status

---

# 4. Approval Provenance

## Requirements

Approval events must record:
- approver
- timestamp
- approval reason
- workflow context
- associated risk level
- override state

---

# Lineage Relationships

## Relationship Types

### Derived From
Dataset B derived from Dataset A.

### Approved By
Action approved by human reviewer.

### Validated By
Artifact validated by validation subsystem.

### Generated By
Output generated by agent/runtime.

### Consumed By
Dataset consumed by downstream workflow.
